# Сборка и релизы

## Что происходит автоматически

В репозитории два workflow GitHub Actions.

**`.github/workflows/ci.yml`** запускается на каждый push в `main` и на каждый
pull request. Проверяет форматирование (`gofmt -l`), затем `make vet`,
`make test` и `make build` на двух архитектурах — `amd64` и `arm64`.

**`.github/workflows/release.yml`** запускается при пуше тега вида `v*`.
Для каждой архитектуры он прогоняет тесты, собирает бинарник, проверяет что
`senso version` печатает версию из тега, и складывает артефакты. Затем job
`publish` собирает всё вместе, считает `SHA256SUMS` и создаёт GitHub Release
с автоматически сгенерированными release notes.

## Матрица сборки

| Платформа    | Раннер             | Артефакты                                                       |
|--------------|--------------------|-----------------------------------------------------------------|
| linux/amd64  | `ubuntu-22.04`     | `.tar.gz`, `senso_<v>_amd64.deb`, `senso-<v>-1.x86_64.rpm`      |
| linux/arm64  | `ubuntu-22.04-arm` | `.tar.gz`, `senso_<v>_arm64.deb`, `senso-<v>-1.aarch64.rpm`     |

Сборка идёт на нативных раннерах, а не кросс-компиляцией: senso требует CGO
(драйвер `mattn/go-sqlite3` и вендоренное расширение `internal/vecext`
написаны на C), поэтому для каждой архитектуры нужен свой компилятор.

Раннер `ubuntu-22.04` выбран намеренно: он даёт glibc 2.35, и бинарник
запускается на дистрибутивах не старше этой версии. Сборка на более свежем
образе подняла бы минимальные требования без всякой пользы.

## Как выпустить версию

```sh
git tag -a v0.2.0 -m "Описание релиза"
git push origin v0.2.0
```

Больше ничего делать не нужно. Версия внутри бинарника берётся из тега:
`Makefile` подставляет `git describe` в `-ldflags`, поэтому `senso version`
покажет ровно то, что было в теге.

Отдельный шаг workflow сверяет вывод `senso version` с именем тега и валит
сборку при расхождении — это защита от релиза с неправильной версией.

## Локальная сборка пакетов

```sh
go install github.com/goreleaser/nfpm/v2/cmd/nfpm@latest
make package
```

Пакеты появятся в `dist/` для текущей архитектуры. Состав пакета описан в
`packaging/nfpm.yaml`: бинарник в `/usr/bin/senso`, документация в
`/usr/share/doc/senso/`.

Версия пакета получается из `VERSION` в `Makefile`: ведущая `v` убирается, а
дефисы заменяются на `~`, потому что rpm не допускает дефис в поле Version.
Сборка не на теге даст версию вида `0.1.0~3~gabc1234`.
