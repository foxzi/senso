# senso: руководство пользователя

## Установка и сборка

Требуется Go (версия указана в `go.mod`) и включённый CGO — драйвер SQLite
(`mattn/go-sqlite3`) и вендоренное расширение `sqlite-vec` (пакет
`internal/vecext`) написаны на C и собираются через cgo.

Все команды `go build`/`go test`/`go vet` **обязаны** запускаться с тегом
сборки `sqlite_fts5`. Без него полнотекстовый движок FTS5 не включается в
сборку `mattn/go-sqlite3`, и senso падает с ошибкой `no such module: fts5`
при первом же обращении к индексу.

Чтобы не забывать про тег, используйте `Makefile`:

```sh
make build   # go build -tags sqlite_fts5 -> ./bin/senso
make test    # go test -tags sqlite_fts5 ./...
make vet     # go vet -tags sqlite_fts5 ./...
make install # установка бинарника
```

Если нужно собрать вручную:

```sh
go build -tags sqlite_fts5 -o bin/senso .
```

## Где хранится база данных

Путь к файлу базы определяется по приоритету (см. `internal/dbpath`):

1. явный флаг `--db <file>`, если он передан любой из команд;
2. переменная окружения `SENSO_DB`, если `--db` не задан;
3. директория `.senso`, найденная поиском вверх по дереву от текущего
   каталога (аналогично тому, как git ищет `.git`) — используется файл
   `<найденный каталог>/.senso/index.db`;
4. если `.senso` нигде не найдена (актуально только для `index`, которая
   умеет создавать базу), создаётся `./.senso/index.db` в **текущем рабочем
   каталоге**, а не рядом с индексируемым путём, а внутрь `.senso` кладётся
   `.gitignore` с содержимым `*`, чтобы служебные файлы никогда не попали в
   git.

Разница из пункта 4 существенна: `senso index ./project` из домашнего
каталога положит базу в `~/.senso/index.db`, а не в `./project/.senso`.
Так база остаётся видимой для последующих `search` и `status`, которые ищут
`.senso` только вверх по дереву и в подкаталог никогда не заглянут.
Чтобы не гадать, куда легла база, `index` печатает в stderr строку
`база: <путь>` (`database: <path>` в английской локали).

Команды `search`, `status` и `rm` базу не создают — если она не найдена, они
завершаются с ошибкой и кодом выхода 1. Это относится и к явному
`--db /путь/с/опечаткой.db`: senso сначала проверяет, что файл существует, и
только потом открывает его. Без этой проверки драйвер SQLite молча создал бы
пустую базу, и вместо понятного «индекс не найден» вы получили бы поиск,
который ничего не находит.

## Язык вывода

Язык человекочитаемого вывода определяется по переменным окружения в
следующем порядке приоритета: `SENSO_LANG`, `LC_ALL`, `LC_MESSAGES`,
`LANG`. Решает первая непустая переменная: если её значение начинается на
`ru` (регистр не важен) — вывод русский, иначе английский; значения `C` и
`POSIX` трактуются как английский. Если ни одна переменная не задана,
вывод английский (это язык по умолчанию).

`SENSO_LANG` — явный override и перекрывает системную локаль в обе
стороны: `SENSO_LANG=en` даёт английский вывод на русской машине,
`SENSO_LANG=ru` — русский на английской.

Локализованы общая справка (`senso help`), описания флагов всех
подкоманд, сообщения об ошибках и подписи в человекочитаемом выводе
`status` и `index`.

Формат JSON (`--json` у `search` и `status`) от локали **не зависит**:
ключи и машиночитаемые значения одинаковы в любой локали — например,
поле `mode` всегда остаётся `lexical` или `lexical+semantic` и никогда не
переводится. Это сделано намеренно, чтобы скрипты не ломались при смене
локали.

Примеры:

```sh
SENSO_LANG=en senso status   # английский вывод независимо от локали ОС
SENSO_LANG=ru senso status   # русский вывод независимо от локали ОС
```

## Команды

Общий вид: `senso <команда> [флаги] [аргументы]`. Команда без аргументов
(`senso` без параметров) и `senso help` печатают краткую справку в stdout и
завершаются с кодом 0. Неизвестная команда печатает ошибку в stderr и
завершается с кодом 2.

### `senso index [флаги] [путь]`

Строит или обновляет индекс для дерева каталогов `путь` (по умолчанию `.`).

Флаги:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--db <file>` | `""` | путь к файлу базы данных |
| `--embed` | `false` | строить векторные эмбеддинги через Ollama; без флага индексация полностью локальная и лексическая, Ollama не требуется |
| `--model <name>` | `bge-m3` | модель эмбеддингов в Ollama (действует только с `--embed`) |
| `--ext <list>` | `""` | список расширений файлов через запятую (пусто = любые) |
| `--exclude <list>` | `""` | список glob-шаблонов исключений через запятую |
| `--no-gitignore` | `false` | не учитывать `.gitignore` |
| `--chunk-size <n>` | `1200` | размер чанка в рунах |
| `--overlap <n>` | `150` | перекрытие чанков в рунах |
| `--query-prefix <s>` | `""` | префикс для поисковых запросов (действует только с `--embed`) |
| `--doc-prefix <s>` | `""` | префикс для документов при индексации (действует только с `--embed`) |
| `--max-file-size <mb>` | `10` | максимальный размер файла в МБ |
| `--concurrency <n>` | `4` | число параллельных обработчиков эмбеддинга (действует только с `--embed`) |
| `--prune` | `true` | удалять из индекса файлы, отсутствующие на диске |
| `--ollama <url>` | `$OLLAMA_HOST` или `http://localhost:11434` | адрес сервера Ollama (действует только с `--embed`) |
| `--quiet` | `false` | не выводить прогресс |

Ограничения: `--chunk-size` > 0, `--overlap` >= 0 и меньше `--chunk-size`,
`--concurrency` > 0, `--max-file-size` > 0 — иначе команда завершится с
ошибкой разбора аргументов (код 2).

Пример:

```sh
senso index .                       # чисто лексическая индексация текущего каталога
senso index --ext go,md ./project   # только .go и .md файлы
senso index --embed .               # + векторные эмбеддинги через Ollama
```

Индексация всегда пропускает служебный каталог `.senso`, `.git`,
`node_modules`, `vendor` и любые скрытые каталоги, а также "шумные" файлы
(`*.lock`, `*-lock.json`, `*.min.js`, `*.min.css`, `*.map`, `*.svg`) — их
исключение нельзя отключить флагами.

Кроме обычных текстовых файлов индексируются офисные документы `.docx`,
`.odt` и `.rtf`: из них извлекается простой текст силами стандартной
библиотеки, никаких внешних конвертеров ставить не нужно. Разметка,
изображения и метаданные отбрасываются, в индекс попадает только текст
абзацев, списков и таблиц, поэтому номера строк в результатах поиска
относятся к извлечённому тексту, а не к исходному файлу. Старый формат
`.doc` (Word 97-2003) не поддерживается — конвертируйте такие файлы в
`.docx` или `.rtf`.

### `senso search [флаги] запрос...`

Ищет по индексу и печатает наиболее релевантные чанки.

**Важно:** флаги нужно указывать перед текстом запроса. Разбор аргументов
останавливается на первом слове, не начинающемся с `-`, поэтому
`senso search "текст" --json` не сработает как ожидается — `--json`
попадёт в текст запроса, а не будет распознан как флаг. Правильно:
`senso search --json "текст"`.

Флаги:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--db <file>` | `""` | путь к файлу базы данных |
| `--k <n>` | `10` | число возвращаемых чанков |
| `--json` | `false` | вывести результаты в формате JSON |
| `--paths-only` | `false` | вывести только уникальные пути файлов |
| `--snippet <n>` | `500` | длина фрагмента текста в результатах, в рунах |
| `--semantic` | `false` | искать по векторам вместо лексического поиска (требует индекса, построенного с `senso index --embed`, и доступной Ollama) |
| `--hybrid` | `false` | объединить лексический и семантический результаты (те же требования, что и у `--semantic`; нельзя вместе с ним) |
| `--ollama <url>` | `$OLLAMA_HOST` или `http://localhost:11434` | адрес сервера Ollama (действует с `--semantic` и `--hybrid`) |
| `--query-prefix <s>` | `""` | префикс для поискового запроса (действует с `--semantic` и `--hybrid`) |

Примеры:

```sh
senso search "поиск и файлы"
senso search --k 5 "конкретный термин"
senso search --json "текст" | jq '.[].path'
senso search --paths-only "текст" | xargs -I{} wc -l {}
senso search --semantic "смысловой запрос про файлы"
senso search --hybrid "точный термин и смысл сразу"
```

#### Форматы вывода

Человекочитаемый (по умолчанию): для каждого результата строка
`путь#номер_чанка  первая_строка-последняя_строка  score`, ниже — с отступом
фрагмент текста длиной до `--snippet` рун. Номера строк относятся к
исходному файлу и позволяют сразу открыть нужное место, например
`vim +40 путь`. Для баз, построенных прежними версиями senso, номера строк
неизвестны и диапазон не печатается — переиндексируйте базу, чтобы он
появился.

Фрагмент печатается с сохранением переносов строк: отступ ставится перед
каждой его строкой, поэтому отступы кода и структура Markdown остаются
читаемыми. Пустые строки по краям фрагмента и хвостовые пробелы убираются.

Фрагмент не обрезается тупо с начала чанка: он центрируется на первом
слове, которое совпало с запросом. Совпадение ищется по основам слов
(тем же стеммингом, что и сам поиск), поэтому запрос `оплата` подсветит
окно вокруг слова «оплате», а префиксный терм `оплат*` — вокруг любого
слова с таким началом. Совпадение ставится примерно на треть ширины окна
слева, чтобы был виден и предшествующий контекст, и продолжение. Обрезанные
края фрагмента помечаются многоточием.

Если совпадение найти не удалось — например, слово попало в соседний чанк
или результат пришёл из семантического поиска, где точного вхождения может
не быть вовсе, — печатается начало чанка, как раньше.

`--json`: массив объектов вида

```json
[
  {
    "path": "/абс/путь/к/файлу.txt",
    "chunk": 0,
    "line_start": 40,
    "line_end": 58,
    "score": 0.478,
    "text": "текст найденного фрагмента"
  }
]
```

Пути всегда абсолютные. Поля `line_start` и `line_end` — номера первой и
последней строки чанка в исходном файле (`0`, если база построена старой
версией senso). Поле `text` собирается тем же способом, что и
фрагмент в человекочитаемом выводе: та же длина `--snippet` и то же
центрирование на совпадении. Если результатов нет, печатается пустой массив
`[]` (валидный JSON, а не пустая строка).

`--paths-only`: список уникальных абсолютных путей файлов, по одному в
строке, без дублей и без оценок.

**Score:** чем больше значение, тем релевантнее результат — в обоих
режимах. В лексическом режиме это инвертированный bm25 (`score = -bm25`,
так как SQLite возвращает bm25 отрицательным и тем меньшим, чем лучше
совпадение). В семантическом режиме это косинусная близость
(`score = 1 - косинусное_расстояние`). В гибридном режиме score — это вес
Reciprocal Rank Fusion: каждый список даёт документу вклад `1 / (60 + позиция)`,
вклады складываются, поэтому документ, попавший в оба списка, обгоняет
документ, лидирующий лишь в одном. Значения из разных режимов между собой
не сравнимы.

### `senso status [флаги]`

Печатает статистику по текущему индексу: путь к базе, корень, режим,
число файлов и чанков, размер базы, время последней индексации и разбивку
по корневым путям.

Одна база может содержать несколько независимых деревьев: каждый запуск
`index` добавляет свой путь в список корней (`meta.roots`), причём корень,
вложенный в уже известный, отдельной записью не становится — его поглощает
предок. Разбивка `roots` показывает число файлов по каждому корню; файл
относится к самому длинному подходящему корню. Пути, не попавшие ни под
один корень (обычно наследие старых баз), собираются в строку `(прочее)`
(`(other)` в английской локали).

Флаги:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--db <file>` | `""` | путь к файлу базы данных |
| `--json` | `false` | вывести статистику в формате JSON |

`--json` печатает объект:

```json
{
  "db": "/абс/путь/.senso/index.db",
  "root": "/абс/путь",
  "mode": "lexical",
  "model": "",
  "dim": 0,
  "files": 3,
  "chunks": 3,
  "fts_rows": 3,
  "vectors": 0,
  "size_bytes": 53248,
  "indexed_at": "2026-08-09T12:20:53+03:00",
  "roots": {"/абс/путь": 2, "/абс/путь/sub": 1}
}
```

Поле `mode` принимает одно из двух машиночитаемых значений: `lexical`
(есть только лексический индекс) или `lexical+semantic` (в базе есть
векторы) — это значение JSON никогда не переводится. В человекочитаемом
выводе та же информация печатается локализованной строкой
`mode: lexical only` / `mode: lexical and semantic` (по умолчанию
английский) либо `режим: только лексический` / `режим: лексический и
семантический` (если язык вывода — русский, см. «Язык вывода» выше).

### `senso rm <путь>`

Удаляет из индекса файл или всё поддерево по указанному пути. На файлы на
диске команда не влияет — только чистит индекс.

Флаги:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--db <file>` | `""` | путь к файлу базы данных |

Ровно один позиционный аргумент — путь (файл или директория). Пример:

```sh
senso rm ./old-directory
senso rm ./notes.txt
```

Вместе с чанками команда чистит список проиндексированных корней
(`meta.roots`, см. `senso status`): если удаляемый путь покрывал целый
зарегистрированный корень, этот корень убирается из списка, иначе он остался
бы висеть в `status` с нулём файлов. Убираются и корни, вложенные в
удаляемый путь; корень-предок сохраняется — под ним могут лежать файлы,
которых удаление не касалось.

### `senso version` и `senso help`

`senso version` (а также `senso --version`) печатает версию сборки одной
строкой:

```
senso v0.1.1 (a1b2c3d, 2026-08-09T12:20:53Z)
```

Версия, коммит и дата берутся из ldflags, которые проставляет `Makefile`
по `git describe`. Если бинарник собран без них, значения восстанавливаются
из встроенной Go информации о сборке (`go install module@version` даёт тег,
рабочее дерево — `vcs.revision` и `vcs.time`). Коммит и дата печатаются в
скобках, только если известны; когда неизвестно ничего, выводится
`senso dev`.

`senso help` (а также `senso -h`, `senso --help` и запуск без аргументов)
печатает список команд. Справка по конкретной команде — `senso <команда>
--help` — собирается из тех же описаний флагов, что использует разбор
аргументов, поэтому она не может разойтись с реальным поведением.

## Использование в пайплайнах и агентами

```sh
# Список путей найденных файлов через jq
senso search --json "ошибка авторизации" | jq -r '.[].path'

# Проверить, есть ли вообще результаты
[ "$(senso search --json "термин" | jq 'length')" -gt 0 ] && echo found

# Прогнать grep по найденным файлам
senso search --paths-only "TODO" | xargs grep -n "TODO"

# Статистика индекса как JSON для мониторинга
senso status --json | jq '.files, .chunks'
```

`--json` и `--paths-only` не смешивают вывод с логами прогресса: прогресс
`index` идёт в stderr, а результаты `search`/`status --json` — в stdout,
что удобно перенаправлять по отдельности.

## Многоязычность

FTS5 настроен с токенизатором `unicode61 remove_diacritics 2` и поддержкой
префиксов (`prefix='2 3'`). Это даёт из коробки:

- работу с русским и английским текстом в одной базе без настройки;
- регистронезависимый поиск (`ПОИСК`, `Поиск` и `поиск` находят одно и то же);
- префиксные запросы: `поис*` находит «поиск», «поисковый» и т.д.;
- склейку букв ё/е (`елка` находит «Ёлка») — это делается вручную в коде
  перед записью в индекс и перед запросом, сам токенизатор такой склейки
  не делает.

**Стемминг.** Индекс и поисковый запрос стеммируются алгоритмом Snowball
(пакет `internal/stem`, зависимость `github.com/kljensen/snowball`, чистый
Go, без cgo). Язык определяется для каждого токена отдельно по наличию
кириллицы, поэтому смешанный русско-английский текст обрабатывается без
определения языка документа целиком. Например, запрос `файл` находит
тексты со словами «файлам» и «файлов», а запрос `search` находит
«searching».

**Синтаксис запроса:**

- обычные слова через пробел ищутся с неявным «И» (нужны все слова);
- фраза в двойных кавычках ищет слова строго подряд, но в любой
  допустимой стеммингом словоформе. В шелле кавычки запроса нужно
  экранировать одинарными, иначе их съест сама оболочка:
  `senso search '"поиск файлов"'` — такой запрос находит текст
  «Поиском файлов занимается индексатор», но не находит
  «Локальный поиск по файлам проекта» — между словами там стоит другое
  слово, и это настоящая проверка соседства, а не просто совпадение слов;
- префикс со звёздочкой (`поис*`) не стеммируется, так как звёздочка уже
  обозначает заведомо неполное слово;
- пунктуация в запросе безопасна и просто отбрасывается, например
  `поиск (файлам)` работает так же, как `поиск файлам`.

**Честные ограничения:**

- Snowball выполняет словоизменение (склонения, спряжения), но не
  словообразование: `индексация` и `индексатор` получают разные стеммы и
  не находят друг друга — это свойство алгоритма, а не дефект.
- буквального поиска «форма в форму», как в `grep`, нет — и обычные слова,
  и фразы ищутся по стеммам; отдельного флага для точного совпадения
  словоформы сейчас не существует.

## Опциональный семантический режим

По умолчанию senso не обращается ни к каким внешним сервисам. Семантический
(векторный) поиск — полностью опциональная надстройка поверх лексического
индекса, полезная когда нужно находить смысловые совпадения, а не только
точные слова.

Что нужно:

- запущенный локальный сервер [Ollama](https://ollama.com);
- модель эмбеддингов, загруженная в Ollama (по умолчанию `bge-m3`).

Как включить:

```sh
senso index --embed .                 # построить индекс с векторами
senso search --semantic "запрос"      # искать по векторам
senso search --hybrid "запрос"        # объединить оба режима через RRF
```

Если индекс уже существует и был построен без `--embed` (только
лексический), повторный запуск `senso index --embed` дозаполнит векторы:
для баз, где таблицы векторов ещё нет, senso принудительно переиндексирует
все файлы через эмбеддинг-модель (даже если mtime/size не менялись),
чтобы у каждого чанка появился вектор.

Если Ollama недоступна в момент `index --embed`, `search --semantic` или
`search --hybrid`,
команда завершается ошибкой (код выхода 1) — senso не переключается тихо
на чисто лексический режим, чтобы не создать частично проиндексированную
базу или не выдать неожиданно другой тип результатов.

## Ограничения

- Snowball покрывает только словоизменение, а не словообразование: `индексация`
  и `индексатор` не находят друг друга, так как получают разные стеммы.
- Нет буквального поиска «форма в форму» (как в `grep`) — весь поиск, включая
  фразы, идёт по стеммам; флага для точного совпадения словоформы нет.
- Нет синтаксического чанкинга кода: файлы любого типа режутся на чанки по
  количеству рун (`--chunk-size`/`--overlap`), без понимания структуры кода
  (функций, классов и т.п.).
- Базы, созданные предыдущими версиями senso, несовместимы с текущей схемой
  (сейчас версия схемы — 3). Любая команда (`index`, `search`, `status`, `rm`)
  откажется работать с такой базой, завершившись с кодом выхода 1 и
  сообщением вида «база создана несовместимой версией senso (схема 2,
  требуется 3), удалите каталог .senso и выполните индексацию заново» —
  лечится удалением каталога `.senso` и повторной индексацией; миграции схемы
  "на лету" не предусмотрено.
